# 🌿 AI Based Employee Wellness Management Platform

MoodMentor is a full-stack employee wellness platform that lets employees log their mood, journal, chat, and get AI-generated wellness suggestions, while giving managers an aggregate, privacy-respecting view of team wellbeing trends. It combines a multilingual NLP pipeline (Telugu/Kannada-aware), facial emotion detection, and an LLM-powered recommendation engine on top of a secure, JWT-authenticated architecture.

## Project Objective

Workplace stress and burnout are often invisible until they become serious. MoodMentor aims to close that gap by giving employees a fast, low-friction way to check in on their mental state — via a mood picker, a journal entry (in their own language), a short wellness questionnaire, or a face scan — and immediately surfacing personalized, LLM-grounded coping suggestions. For managers, the platform aggregates this data into an anonymized analytics dashboard so at-risk trends can be spotted and supported early, without exposing any individual's private entries.

## Project Architecture

MoodMentor runs as two cooperating services in front of a managed Postgres database:

```
┌─────────────────────┐        JWT-authenticated         ┌──────────────────────┐
│   Streamlit Frontend │ ───────── HTTP requests ───────▶ │   FastAPI Backend     │
│       (app.py)       │ ◀──────── JSON responses ─────── │     (backend.py)      │
└──────────┬───────────┘                                  └──────────┬───────────┘
           │                                                         │
           │ direct DB access                          nlp_pipeline.py (NLP/ML)
           ▼                                                         │
┌──────────────────────┐                                             ▼
│  Managed PostgreSQL   │ ◀──────────────── writes/reads ───  Sentiment, emotion,
│ (Neon / Supabase etc) │                                     translation, chat
└──────────────────────┘
```

- **Frontend (`app.py`)** — a Streamlit single-page app handling authentication UI, mood/journal entry, the wellness questionnaire, face scanning (via OpenCV + DeepFace), the manager dashboard, and rendering LLM-generated suggestions.
- **Backend (`backend.py`)** — a FastAPI service that validates the same JWT issued at Streamlit login, and exposes endpoints for file upload, text/file NLP analysis, and the wellness chat.
- **Shared modules** — `db.py` (Postgres access + schema management), `auth.py` (JWT + OTP auth), `security.py` (input sanitization), `email_utils.py` (SMTP OTP delivery), `recommendations.py` (rule-based, score-band suggestions), `nlp_pipeline.py` (language detection, translation, sentiment/emotion models).
- **Deployment options** — run everything inside the provided Colab notebook (tunneled out via ngrok, good for demos), or deploy the same modules as two Docker containers (backend + frontend) behind a managed Postgres instance for a stable, always-on URL.

All timestamps (mood entries, journal submissions, OTPs) are recorded in a fixed IST (+5:30) offset, kept consistent between the frontend and backend regardless of the host machine's own timezone.

## Key Features

- **Multi-channel mood capture** — quick emoji mood picker, free-text journal entries, a scored wellness questionnaire, and webcam-based facial emotion scanning, all logged to a single unified mood history per user.
- **Multilingual NLP analysis** — detects the input language (with explicit Telugu/Kannada awareness), cleans and tokenizes text, translates it to English, lemmatizes it, and runs VADER sentiment scoring plus BERT-based emotion classification.
- **File and text analysis endpoints** — upload a `.csv`/`.txt` file or type directly into the Journal tab; both paths run through the same NLP pipeline.
- **LLM-powered wellness suggestions** — personalized coping suggestions generated by a Groq-hosted Qwen model, grounded in what the user actually wrote (no generic static fallback).
- **Wellness chat** — a conversational chat endpoint for in-the-moment support.
- **Role-based accounts** — employees and managers sign up separately; managers get access to an aggregate-only Analytics Dashboard, never individual entries.
- **Risk detection** — flags employees showing a sustained negative-mood streak so managers can offer support proactively.
- **Rule-based fallback recommendations** — score-band tips for the questionnaire and manager-facing team recommendations that don't depend on the LLM being available.
- **Secure authentication** — JWT-based sessions shared between frontend and backend, bcrypt password hashing, and email OTP verification for signup and password reset.
- **Exportable history** — activity log and CSV/PDF export of a user's mood history and charts.

## Application Highlights

- **Home** — landing dashboard with a quick mood check-in and backend connectivity status.
- **Journal** — free-text journaling with automatic language detection, translation, and sentiment/emotion analysis, plus LLM-grounded suggestions.
- **Analyze My Mood** — a structured wellness questionnaire scored into bands (Thriving → At Risk), each with tailored, escalation-aware recommendations.
- **Wellness Chat** — a lightweight conversational support surface backed by the NLP/LLM pipeline.
- **Face Scanner** — webcam-based facial emotion detection mapped onto the same emotion vocabulary used elsewhere in the app.
- **Dashboard** — personal mood history, calendar view, and exportable reports.
- **Analytics Dashboard (Manager only)** — aggregate, anonymized team mood trends and risk-streak alerts — individual employee entries are never exposed.

## Running the Application

### Option A — Google Colab (demo/development)

1. Open the notebook in Google Colab.
2. Add the required secrets via the Colab **Secrets** panel (🔑 icon): `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD`, `SMTP_EMAIL`, `SMTP_APP_PASSWORD`, `NGROK_AUTHTOKEN`. `JWT_SECRET` is auto-generated if omitted, and `GROQ_API_KEY` is optional (enables LLM wellness suggestions).
3. Run the cells top to bottom: install dependencies → write `.env` → write `db.py`, `security.py`, `recommendations.py`, `auth.py`, `email_utils.py`, `app.py`, `nlp_pipeline.py`, `backend.py` to disk → launch the FastAPI backend and Streamlit frontend, tunneled out via ngrok.
4. Open the printed ngrok URL to use the app.

> Note: installing spaCy and downloading its `xx_sent_ud_sm` model adds a few minutes to the first run in a fresh Colab runtime. The ngrok URL is temporary and the app stops if the Colab runtime disconnects — use Docker for anything long-running.

The database schema is created and upgraded automatically on backend startup (`init_db()`), so no separate migration step is required.

### Running tests

Pure-function unit tests (questionnaire scoring, rule-based recommendations, password hashing, input sanitization) require no database, network access, or loaded ML models, and are safe to run in CI:

```bash
pytest test_moodmentor.py
```

An optional benchmark script (`evaluate_model.py`) validates the emotion classifier against the public `dair-ai/emotion` dataset and reports accuracy/precision/recall/F1 — this needs network access and the loaded BERT model, so it's intended for Colab rather than offline environments.

## Security

- **JWT-based authentication** — a single `JWT_SECRET` issues and verifies tokens shared between the Streamlit frontend and FastAPI backend; the backend rejects any request with a missing, invalid, or expired token.
- **Password hashing** — user passwords are hashed with bcrypt; plaintext passwords are never stored.
- **Email OTP verification** — signup and password-reset flows require a one-time code sent via SMTP (Gmail App Password, not the real account password), with a configurable expiry window.
- **Input sanitization** — all free-text input (journal entries, chat messages, uploaded file text) is passed through `bleach`-based sanitization at both the UI entry point and again at the API layer (defense in depth), stripping HTML/script markup and capping input length before it reaches the NLP pipeline or database.
- **File upload validation** — the `/upload` endpoint only accepts `.csv`/`.txt` files, enforces a 5 MB size cap, and requires valid UTF-8 text.
- **Role-based access control** — manager-only views (Analytics Dashboard) are gated by account role; the aggregate dashboard never exposes individual employees' raw entries.
- **TLS to the database** — Postgres connections require SSL (`sslmode=require`).
- **Secrets management** — all credentials (database, JWT, SMTP, ngrok, Groq) are supplied via environment variables (`.env`, Colab Secrets, or Docker `env_file`) and are never hard-coded; `.env` is excluded from version control via `.dockerignore`/`.gitignore` conventions.
